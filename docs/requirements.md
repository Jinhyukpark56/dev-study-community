# 첫 버전 요구사항 v0.1

상태: 검토 가능한 기획 초안. 사용자와 합의한 커뮤니티 방향을 구체화한 제안입니다.

## 목적과 사용자

개발 공부 중 막힌 질문과 학습 기록을 남기고 댓글로 의견을 나누는 서비스입니다.
주 사용자는 개발 공부를 하는 사람입니다. 첫 버전의 성공 기준은 실제 사용자가 가입하고 글을 쓰며 다른 사용자가 댓글을 남길 수 있는 것입니다.

## 대표 사용 흐름

질문과 학습 기록은 별도 게시판 없이 하나의 최신순 목록에 함께 표시합니다. 사용자 확인 완료. 첫 버전에 글 유형별 필터는 추가하지 않습니다. 글 유형은 작성 시 선택하고 목록에 표시합니다.

1. 방문자가 최신 글 목록과 상세 내용을 읽습니다.
2. 계정을 만들고 로그인합니다.
3. 질문 또는 학습 기록을 선택해 제목·본문·태그를 입력합니다.
4. 다른 사용자가 글을 읽고 댓글을 작성합니다.
5. 작성자가 글을 수정하거나 삭제합니다.
6. 사용자가 로그아웃합니다.

## 기능과 완료 기준

| ID | 기능 | 확인할 동작 |
| --- | --- | --- |
| R01 | 회원가입 | 사용 가능한 email과 비밀번호로 가입 성공. 중복 email과 잘못된 입력은 거부 |
| R02 | 로그인·로그아웃 | 올바른 자격정보로 로그인. 실패 시 ID 존재 여부를 구분하지 않는 오류 표시. 로그아웃 후 보호된 기능 사용 불가 |
| R03 | 게시글 작성 | 로그인한 사용자가 질문 또는 학습 기록 등록. 저장 후 상세 조회 가능 |
| R04 | 목록·상세 조회 | 비로그인 상태에서도 조회 가능. 없는 글은 찾을 수 없다는 결과 표시 |
| R05 | 게시글 수정·삭제 | 작성자만 성공. 다른 사용자 요청은 거부되고 데이터는 유지 |
| R06 | 댓글 작성·조회·수정·삭제 | 조회는 누구나 가능. 로그인 후 작성. 작성자만 수정·삭제. 없는 게시글에는 작성 불가 |
| R07 | 태그별 목록 | 선택한 태그가 연결된 글만 조회. 결과가 없으면 빈 목록 표시 |
| R08 | 페이지네이션 | 기본 20개. 최신순으로 안정적인 순서 제공. 마지막 다음 페이지는 빈 목록 |
| R09 | 배포 검증 | 별도 브라우저 또는 테스트 계정 두 개로 가입→글→댓글→권한 거부→삭제→로그아웃 확인 |

## 입력 규칙 제안

- email: 앞뒤 공백 제거와 소문자 정규화 후 검사. 최대 254자, `@` 한 개, 공백 없음, 중복 불가.
- 비밀번호: 최소 15자, 현재 BCrypt 기준 최대 72 UTF-8 byte. 공백을 임의로 제거하거나 문자열을 변형하지 않음. 원문 저장·응답·로그 출력 금지.
- 글 유형: QUESTION 또는 STUDY_LOG 중 하나.
- 제목: 앞뒤 공백 제거 후 1~100자.
- 본문: 공백만 입력은 거부. 최대 10,000자. 줄바꿈 유지. 첫 버전은 일반 텍스트로 표시하며 HTML 실행 금지.
- 댓글: 공백만 입력은 거부. 최대 1,000자. 일반 텍스트.
- 태그: 운영자가 코드 또는 초기 데이터로 준비한 목록에서 글당 최대 3개 선택. 첫 버전에서는 사용자가 태그를 생성하지 않음.
- 문자열 길이 계산의 기준은 구현 전 정하고 화면과 서버에 동일하게 적용.
- 페이지 번호는 0부터, 크기는 1~50. 범위를 벗어난 입력은 오류 처리.

## 데이터와 권한 규칙

- 생성 시각은 서버에서 기록. 수정해도 생성 시각은 유지.
- 글 목록 정렬: 생성 시각 내림차순, ID 내림차순.
- 댓글 정렬: 생성 시각 오름차순, ID 오름차순. 댓글도 페이지 단위로 조회.
- 작성자 ID는 로그인 정보에서 결정. 클라이언트가 보내는 작성자 ID를 신뢰하지 않음.
- 게시글 삭제 시 게시글 본문과 모든 댓글, 글-태그 연결을 함께 삭제합니다. 삭제된 글의 자리는 남기지 않습니다. 사용자 확인 완료. 다른 글에서도 쓰는 태그 자체는 유지합니다.
- 이미 삭제된 글·댓글에 대한 수정·삭제는 찾을 수 없다는 결과로 처리.
- 비밀번호 찾기·회원 탈퇴·첨부파일·대댓글·좋아요·검색·신고·채팅·AI 기능은 후속 범위.
- 첫 배포는 소수 테스트 사용자의 피드백 수집 목적. 공개 운영 전 계정 복구·탈퇴 등 운영 요구사항을 다시 검토.

## 주요 검증 사례

- 사용자 A의 글을 B가 수정·삭제할 수 없는가?
- 로그아웃 후 같은 작성 요청을 다시 보내면 거부되는가?
- 공백 제목, 너무 긴 본문, 존재하지 않는 태그가 저장되지 않는가?
- 같은 email로 동시에 가입해도 하나의 계정만 생성되는가?
- 같은 생성 시각의 글도 동일 데이터 상태에서 목록 순서가 유지되는가?
- 글 삭제 후 댓글이나 글-태그 연결이 남지 않는가?
- 본문에 HTML 형태의 문자열을 넣어도 실행되지 않고 텍스트로 보이는가?

완료는 화면 동작만으로 판단하지 않습니다. 권한·입력 검사는 서버에서도 검증하고 핵심 실패 사례를 테스트합니다.
