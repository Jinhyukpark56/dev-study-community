# 첫 버전 요구사항 v0.1

상태: 기능 구현 완료, 2026-10-20 통합 코드 리뷰 대기. 외부 배포와 실제 사용자 피드백 수집은 미완료입니다.

## 목적과 사용자

개발 공부 중 막힌 질문과 학습 기록을 남기고 댓글로 의견을 나누는 서비스입니다. 주 사용자는 개발 공부를 하는 사람입니다. v0.1의 제품 성공 기준은 실제 사용자가 가입하고 글을 쓰며 다른 사용자가 댓글을 남길 수 있고, 작성자 권한과 데이터 영속성이 배포 환경에서도 유지되는 것입니다.

## 대표 사용 흐름

질문과 학습 기록은 별도 게시판 없이 하나의 최신순 목록에 함께 표시합니다. 글 유형은 작성 시 선택하고 목록·상세에 표시합니다.

1. 방문자가 최신 글 목록과 상세 내용을 읽습니다.
2. 계정을 만들고 로그인합니다.
3. 질문 또는 학습 기록을 선택해 제목·본문·태그를 입력합니다.
4. 다른 사용자가 글을 읽고 댓글을 작성합니다.
5. 각 작성자가 자신의 글이나 댓글을 수정·삭제합니다.
6. 태그를 선택해 관련 글을 보고 페이지를 이동합니다.
7. 사용자가 로그아웃합니다.

## 입력 규칙

- email: 앞뒤 공백 제거와 소문자 정규화 후 검사. 최대 254자, `@` 한 개, 공백 없음, 중복 불가.
- password: 최소 15자, 현재 BCrypt 기준 최대 72 UTF-8 byte. 공백을 임의로 제거하거나 문자열을 변형하지 않음. 원문 저장·응답·로그 출력 금지.
- 글 유형: `QUESTION` 또는 `STUDY_LOG`. 생략하면 `STUDY_LOG`.
- 제목: null·공백만인 값 거부, `String.length()` 기준 최대 100자.
- 본문: null·공백만인 값 거부, `String.length()` 기준 최대 1000자. 줄바꿈을 유지하고 일반 텍스트로 표시.
- 댓글: null·공백만인 값 거부, `String.length()` 기준 최대 1000자. 일반 텍스트로 표시.
- 태그: 입력한 이름을 앞뒤 공백 제거 → 연속 공백 한 칸 → 소문자로 정규화. 이름당 최대 50자, 게시글당 서로 다른 이름 최대 3개. 기존 이름은 재사용하고 새 이름은 생성.
- 페이지: 0부터 시작하고 크기는 1~50. 기본값은 `page=0`, `size=20`. 범위를 벗어난 입력은 400.

제목·본문·댓글은 서버가 입력 문자열의 앞뒤 공백을 별도로 제거해 저장하지 않습니다. 공백으로만 이루어진 값은 `isBlank()`로 거부합니다. 화면과 서버 규칙을 바꾸면 양쪽을 함께 수정합니다.

## 데이터와 권한 규칙

- 생성 시각은 서버에서 기록하고 수정해도 유지합니다. 수정 시각은 생성할 때 같은 값으로 시작하고 변경 시 갱신합니다.
- 글 목록 정렬은 생성 시각 내림차순, 같은 시각에는 ID 내림차순입니다. 이전 데이터의 null 시각은 뒤에 둡니다.
- 댓글 정렬은 생성 시각 오름차순, 같은 시각에는 ID 오름차순입니다. 현재 v0.1의 댓글 목록은 페이지네이션 없이 반환합니다.
- 작성자 ID는 로그인 정보에서 결정합니다. 클라이언트가 보내는 작성자 ID를 신뢰하지 않습니다.
- 비로그인 사용자는 글·댓글을 읽을 수 있고, 쓰기 요청에는 Authentication과 CSRF token이 필요합니다.
- 글·댓글 수정과 삭제는 작성자 PK가 현재 사용자 PK와 같을 때만 허용합니다.
- 게시글 삭제 시 모든 댓글과 글-태그 연결을 같은 트랜잭션에서 제거합니다. 삭제된 글의 자리는 남기지 않습니다. User와 다른 글에서도 쓰는 Tag Entity는 유지합니다.
- 댓글 삭제는 Post나 User 삭제로 전파되지 않습니다. Post–Tag에도 cascade remove를 사용하지 않습니다.
- 이미 삭제된 글·댓글 또는 URL의 게시글과 실제 댓글 소속이 다른 요청은 404로 처리합니다.
- 비밀번호 찾기·회원 탈퇴·첨부파일·대댓글·좋아요·검색·신고·채팅·AI 기능은 후속 범위입니다.
- 첫 배포는 소수 테스트 사용자의 피드백 수집 목적입니다. 공개 운영 전 계정 복구·탈퇴, 인증 요청 제한, backup과 개인정보 운영 요구사항을 다시 검토합니다.

## 응답과 화면 규칙

- `GET /posts`는 게시글 배열이 아니라 `content/page/size/totalPages/totalElements` 페이지 객체를 반환합니다.
- 조회 응답에는 작성자 ID만 포함하며 User Entity나 password hash를 포함하지 않습니다.
- 400은 입력 오류, 401은 로그인 필요, 403은 작성자 권한 없음 또는 CSRF 오류, 404는 대상 없음입니다.
- 최소 UI는 로그인 상태와 작성자 여부에 맞는 버튼을 보여주지만, 최종 권한 판단은 서버가 수행합니다.
- 사용자 입력은 HTML로 실행하지 않고 텍스트로 렌더링합니다.
- 500 오류 메시지에 내부 예외, stack trace, DB 정보, secret을 노출하지 않습니다.

## 주요 검증 사례

- 사용자 A의 글과 댓글을 B가 수정·삭제할 수 없는가?
- 로그아웃 후 같은 쓰기 요청을 다시 보내면 401인가?
- CSRF token이 없거나 잘못된 unsafe 요청이 403인가?
- 공백 제목·본문·댓글, 길이 초과, 태그 4개, 잘못된 페이지가 저장 또는 조회되지 않는가?
- 같은 email로 동시에 가입해도 DB unique 제약으로 하나의 계정만 남는가?
- 태그의 대소문자·연속 공백 차이가 정규화되고 같은 Tag를 재사용하는가?
- 같은 생성 시각의 글도 동일 데이터 상태에서 목록 순서가 유지되는가?
- URL의 `postId`와 실제 Comment의 Post가 다르면 404이고 데이터가 유지되는가?
- 글 삭제 후 댓글과 `post_tags` 연결은 없어지고 User와 공유 Tag는 남는가?
- 게시글 삭제 도중 실패하면 먼저 삭제한 댓글도 rollback되는가?
- 본문·댓글에 HTML 형태의 문자열을 넣어도 실행되지 않고 텍스트로 보이는가?
- PostgreSQL과 HTTPS 환경에서 Session, CSRF, Secure cookie, DB readiness가 동작하는가?

완료는 화면 동작만으로 판단하지 않습니다. 서버 권한·Validation·transaction을 자동 테스트로 확인하고, 외부 배포 완료 전에는 구현 완료와 출시 완료를 구분합니다.
