# 게시글 API 초안

사용자와 논의한 요청 경로입니다. 구현 전 단계이며 JSON 필드와 인증 방식의 세부 계약은 아직 미확정입니다.

| 행동 | 요청 | 성공 응답 초안 | 권한 |
| --- | --- | --- | --- |
| 목록 조회 | GET /posts | 200, 게시글 목록 | 누구나 |
| 상세 조회 | GET /posts/{id} | 200, 게시글 상세 | 누구나 |
| 작성 | POST /posts | 201, 생성된 게시글 및 Location | 로그인 사용자 |
| 수정 | PATCH /posts/{id} | 200, 수정된 게시글 | 작성자 |
| 삭제 | DELETE /posts/{id} | 204, 본문 없음 | 작성자 |

## 요청 규칙

- 작성 요청에는 유형, 제목, 본문, 선택한 태그 ID들을 보냅니다.
- 글 ID, 작성자 ID, 작성·수정 시각은 서버가 결정합니다.
- 수정에서는 전달된 수정 가능 필드만 변경하고 생략된 필드는 유지합니다. null은 거부하는 초안입니다.
- 글 ID와 작성자, 작성 시각은 수정할 수 없습니다.
- 목록은 page=0, size=20을 기본값으로 사용하고 태그 ID 필터를 선택적으로 받는 초안입니다. 유형별 필터는 없습니다.
- 화면에서 버튼을 숨기더라도 서버가 로그인과 작성자 권한을 반드시 검사합니다.
- 게시글 삭제는 댓글과 글-태그 연결의 삭제까지 하나의 트랜잭션으로 처리합니다. 일부만 삭제되고 실패하지 않도록 검증합니다.

## 실패 응답 초안

| 상태 코드 | 의미 | 예시 |
| --- | --- | --- |
| 400 | 요청 입력이 잘못됨 | 빈 제목, 길이 제한 초과, 잘못된 페이지 번호 |
| 401 | 로그인 필요 | 비로그인 사용자가 글 작성 요청 |
| 403 | 작업 권한 없음 | 다른 사용자의 글을 수정·삭제하려는 요청 |
| 404 | 대상 없음 | 존재하지 않거나 삭제된 글 조회 |
| 500 | 예상하지 못한 서버 오류 | 내부 실패. 응답에 내부 예외나 비밀정보를 노출하지 않음 |

로그인이 필요한 요청은 인증 검사를 먼저 수행합니다. 인증된 요청은 대상 존재 여부를 확인한 뒤 작성자 권한을 검사합니다.
이 문서의 상태 코드와 응답 상세는 초안이며 실제 구현 및 테스트에서 일치하도록 관리합니다.
