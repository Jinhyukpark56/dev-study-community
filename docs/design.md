# 설계 초안

상태: User·Post·Session 인증·게시글 작성자 인가는 구현되었습니다. 댓글·태그·게시글 유형·시각 필드는 v0.1 후속 설계 범위입니다.

## 데이터 관계

| 데이터 | 현재 또는 목표 항목 | 관계 | 상태 |
| --- | --- | --- | --- |
| 사용자 | ID, email, 비밀번호 해시 | 여러 글을 작성 | 구현 |
| 게시글 | ID, 작성자 ID, 제목, 본문 | 사용자 한 명에 속함 | 구현 |
| 게시글 후속 필드 | 유형, 생성·수정 시각 | 기존 게시글에 추가 | v0.1 후속 |
| 댓글 | ID, 게시글 ID, 작성자 ID, 본문, 생성·수정 시각 | 글 하나와 사용자 한 명에 속함 | v0.1 후속 |
| 태그 | ID, 이름 | 여러 게시글에 연결 | v0.1 후속 |
| 게시글-태그 | 게시글 ID, 태그 ID | 두 값의 조합은 중복 불가 | v0.1 후속 |

email 중복은 애플리케이션 검사와 데이터베이스의 유일성 제약으로 막습니다.
게시글-태그는 글 하나가 여러 태그를 갖고 태그 하나가 여러 글에 붙는 관계를 표현합니다.
댓글·태그 구현 뒤 게시글 삭제 시 연관 데이터 처리와 트랜잭션 경계를 테스트 시나리오와 함께 구체화합니다.

## Post–User 관계와 작성자 인가 — 2026-09-29 구현

- `Post.author`에 `@ManyToOne(optional = false)`를 사용하고 `@JoinColumn(name = "author_id", nullable = false)`로 필수 외래 키를 저장합니다.
- 관계는 `Post`에서 `User`로만 탐색하는 단방향입니다. 현재 요구에 필요하지 않은 `User.posts` 컬렉션은 만들지 않았습니다.
- author에는 cascade를 설정하지 않습니다. 게시글 저장·삭제가 사용자 생명주기를 변경하지 않게 합니다.
- author를 바꾸는 setter를 제공하지 않습니다. 게시글 작성 시 로그인 사용자로 한 번 정하고 이후 수정 대상에서 제외합니다.
- `PostController`는 클라이언트의 작성자 입력을 받지 않고 `Authentication`의 email로 현재 `User`를 조회합니다. 따라서 다른 사용자 ID를 넣어 작성자를 가장할 수 없습니다.
- `PostResponse`는 `id/title/content/authorId`만 반환해 `User` Entity와 password hash를 HTTP 응답에 노출하지 않습니다.
- 수정 트랜잭션은 대상 조회 → 작성자 ID 비교 → 전체 입력 검증 → 값 변경 순서입니다. 성공 시 Dirty Checking으로 반영하고, 403·400이면 Entity를 변경하기 전에 종료합니다.
- 삭제 트랜잭션은 대상 조회 → 작성자 ID 비교 → 삭제 순서입니다.

`Post.author.id`와 현재 `User.id`를 비교하므로 JPA Entity 객체가 같은 Java 참조인지와 관계없이 동일 작성자를 판별합니다. 비로그인 쓰기 요청은 Security Filter에서 401, 다른 로그인 사용자의 수정·삭제는 Service 결과를 통해 403, 없는 게시글은 404로 구분합니다. CSRF token이 없거나 잘못된 unsafe 요청은 작성자 검사 전에 403으로 차단됩니다.

## 게시글 데이터 상세

사용자와 확인한 기본 항목입니다. 현재 구현된 항목과 v0.1 후속 항목을 구분합니다.

| 항목 | 예시 | 목적과 규칙 | 상태 |
| --- | --- | --- | --- |
| 글 ID | 101 | 글을 고유하게 구분. 제목이 같아도 다른 글이며 수정해도 ID는 유지. DB에서 생성 | 구현 |
| 작성자 ID | 7 | 사용자 데이터와 연결. 로그인한 사용자에서 결정하고 클라이언트 입력으로 지정하지 않음 | 구현 |
| 제목 | Java return이 궁금합니다 | 목록에 표시. 공백 불가, 최대 100자 | 구현 |
| 본문 | 출력과 반환은 어떻게 다른가요? | 상세 화면에 표시. 공백 불가, 최대 1000자 | 구현 |
| 유형 | QUESTION | 질문 또는 학습 기록. 하나의 목록에 함께 표시 | v0.1 후속 |
| 작성 시각 | 2026-09-08T10:00:00Z | 최초 저장 시 서버에서 기록하고 수정 시에도 유지 | v0.1 후속 |
| 수정 시각 | 2026-09-08T10:05:00Z | 생성 시 작성 시각과 동일하게 설정하고 수정 시 갱신하는 초안 | v0.1 후속 |

현재 최소 인증 Entity에는 닉네임을 추가하지 않습니다. 작성자 표시 이름은 v0.1 후속 요구사항에서 별도로 결정합니다.
댓글은 게시글 내부의 문자열로 합치지 않고 별도 데이터로 저장해 게시글 ID로 연결합니다.
태그도 별도 연결 데이터로 관리합니다. 예를 들어 게시글 101과 태그 3의 연결은 (101, 3)으로 표현합니다.

### 예시로 보는 관계

- 사용자 7이 게시글 101 작성
- 사용자 8이 게시글 101에 댓글 501 작성
- 댓글 501에는 작성자 ID 8과 게시글 ID 101이 저장됨
- 게시글 101을 삭제하면 댓글 501과 글-태그 연결도 삭제됨
- 사용자 7·8의 계정과 다른 글에서 사용하는 태그는 유지됨

## 첫 화면 구성

- 목록: 글 유형, 제목, 작성자, 작성일, 태그, 페이지 이동
- 상세: 글 내용, 작성자용 수정·삭제, 댓글 목록과 작성, 본인 댓글 수정·삭제
- 작성·수정: 유형, 제목, 본문, 태그 선택
- 인증: 회원가입, 로그인, 로그아웃

시각 디자인은 핵심 API 검증 뒤 진행합니다.

## 기술 결정 상태

| 항목 | 현재 결정 | 상태 |
| --- | --- | --- |
| 언어와 서버 | Java 21 + Spring Boot 4.1.1 | 구현·검증 |
| 빌드 도구 | Gradle 9.7.1 Wrapper | 구현·검증 |
| 개발·테스트 DB | 개발은 파일형 H2, 테스트는 메모리 H2 | 구현·검증 |
| 배포 DB | 관계형 DB, PostgreSQL 또는 MySQL 검토 | 첫 배포 전 결정 |
| 데이터 접근 | Spring Data JPA | 구현·검증 |
| 인증 | Spring Security form login + HTTP Session + CSRF | 구현·검증 |
| 게시글 작성자 인가 | Post–User 외래 키와 Service의 작성자 ID 비교 | 구현·코드 리뷰·이해 확인 완료 |
| 배포 | 비용·운영 부담을 확인한 후 선정 | 첫 배포 전 결정 |

처음부터 캐시 서버, 메시지 큐, 여러 서비스로의 분리를 추가하지 않습니다. 측정된 문제나 실제 요구가 생기면 도입 이유와 대안을 기록합니다.
Session cookie, CSRF 방어, 로그아웃 시 Session 무효화를 인증 구현에 포함했습니다.

게시글 작성자 인가 구현은 40개 전체 테스트를 통과했습니다. 2026-09-30 ChatGPT 실제 코드 리뷰와 사용자 이해 확인을 완료했으며, 현재 학습 범위에서 즉시 수정해야 할 핵심 문제는 발견되지 않았습니다.
